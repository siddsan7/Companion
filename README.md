# Companion

A local Windows desktop capture app for an Obsidian vault. No account or network connection is needed for capture and browsing.

Use Node.js 24 and npm. Run `npm ci`, `npm run prepare:electron`, then `npm start`. Preparation downloads and verifies the pinned Windows Electron runtime before the app starts. Select your vault directory, enter a relative parent folder, and select **Use this folder**. Save a thought or an HTTP(S) link. Titles are derived automatically and can be edited. **Add source excerpt** associates pasted text with a link and labels it as user supplied. Companion never fetches the page.

**Today** uses the PC's current timezone, shown above the capture list. **All captures** and local text search retain access to older notes. Refresh, window focus, and a one-minute refresh update date grouping. **Open in Obsidian** uses the installed application's `obsidian://open` handler.

The chosen parent contains `Captures`, `Annotations`, `Ideas`, `Briefs`, and `Revisions`. Captures and validated Reel to MD imports use these areas. Capture notes are readable Markdown with a stable UUID, schema version and absolute first-capture instant in frontmatter. Title edits retain the same file and identity. Settings live outside the vault in Electron's local user-data directory. Notes have no automatic expiry.

New notes publish from a flushed adjacent staging file using an exclusive hard link. Existing files cannot be replaced by capture creation. Interrupted quick captures recover after their owning process exits. Title edits detect changes since loading, journal the proposed content, move the old file to an adjacent `.bak` file, then publish without replacing an existing destination. Interrupted title saves recover on restart and show a notice. Recovery backups retain changes made through a previously opened editor handle. Inspect both files if Companion reports a conflict. Existing junctions that point outside the vault are refused. Damaged capture metadata reports its filename and preserves valid captures. A copied identity blocks edits until you review and choose the managed file in **Vault repairs**. Companion preserves independent writing and does not infer deletion from an inaccessible vault.

Connect a Reel to MD draft output folder in **Reel intake**. **Scan existing drafts now** is optional. **Check now** uses the same locked worker as scheduled intake. **Enable daily intake** explicitly registers one Windows task under the signed-in user. Its first check is 24 elapsed hours after setup; Windows boundaries round upward by less than one second while Companion retains the exact anchor. Later checks repeat every 24 hours with the UI closed. Early UI launch does not scan; missed checks coalesce when a due worker becomes available. Windows may delay catch-up. The task does not intentionally wake the PC or run while signed out.

**Pause daily intake** blocks queued checks and lets an admitted import finish. **Resume daily intake** retains the anchor. **Disable daily intake** removes the exact owned task and preserves sources, notes and the anchor. **Repair daily intake** checks task ownership and restores its definition. The schedule shows last success, errors and effective enabled-state differences. Keep this development checkout and its Electron runtime available until an installer supplies a stable installation. Natural 24-hour recurrence and sleep/sign-out behavior remain unobserved; see [ticket 6 verification](docs/verification-ticket6.md).

After installing locked dependencies, run `npm run prepare:electron`, `npm run check`, then `npm test`. The check validates UTF-8, JavaScript and PowerShell syntax for tracked sources and compares the native probe to its existing hashes. It does not execute the PowerShell scripts or rebuild the probe. Playwright uses actual Electron and disposable vaults. Fixtures control folder selection, time, provider responses and Obsidian URI capture. Never set `COMPANION_TEST_ROOT` for a real vault. The renderer has no Node or network access.

Companion includes approved MyTune briefs, reviewed context, local conversation history, saved ideas and Experiment Proposals, deliberate source deletion, and local history archives. Production chat and comparison remain closed while the live signed-in checks are deferred. A saved proposal is an idea to test, not an executed experiment. The desktop and local data workflows do not depend on live chat.
