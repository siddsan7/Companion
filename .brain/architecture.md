# Runtime map

- `app/main.js`: Electron lifecycle; folder-selection/settings, IPC, clock and Obsidian OS boundary. `COMPANION_TEST_ROOT` substitutes those boundaries for disposable acceptance runs.
- `app/preload.js`: narrow renderer-to-main bridge. Renderer Node access is disabled; sandbox, context isolation, CSP and blocked network/navigation apply.
- `app/vault.js`: authoritative Markdown capture store. Exclusive staged publication, stable UUID frontmatter, first capture instant, derived/editable title, user excerpt provenance. No index or database owns note content.
- `app/repairs.js`: shared-lock conflict transfer, missing/duplicate identity choices and guarded relationship journals. Vault-wide validated annotation scans retain moved-note associations; annotation duplicate choices use `annotation:<UUID>` keys separately from capture choices. Only the immediate generated header link after the first frontmatter block is repair-owned. Editor conflicts retain immutable link intent/peer evidence and an annotation-specific ledger hold; explicit retry rechecks current identities/bytes while source intake continues. Independent body text remains user-owned.
- `app/renderer.js`, `index.html`, `style.css`: capture, timezone-aware Today, history/search, title edit, open-note workflow.
- `app/intake-producer.js`, `producer-schema/`: Reel to MD draft envelope, strict schema/semantic revalidation, bound-excerpt restrictions, stable multi-file read and exact inert/redacted notes comparison. Supported draft review is unreviewed; extraction completeness and uncertainty are separate.
- `app/intake.js`: vault-owned `.intake/ledger.json`, immutable accepted attempts separate from locator outcomes, staged snapshot/journal publication, title intent recovery, immutable `Revisions/<uuid>.json`, source-byte grouping and distinct producer attempts. Source conflicts retain incoming/local/previous versions and pause that source while independent intake continues. Capture access failures defer per source; only explicit Check now retries them. Stage/final files require ordinary contained files and exact known hardlink peers for recovery. It does not copy media. Source connection, first/manual checks and scheduled/catch-up workers share this entry point and native lock.
- `app/intake-lock.js`: canonical-vault kernel-owned named-pipe lock on Windows; process death releases it without racing stale PID reclamation. Reconciliation, connection and imported title mutation use the same lock.
- `app/intake-view.js`: source connection, first-scan choice, held reasons, last check and source/revision inspection. Sections have named navigation as the shell grows.
- `tests/capture.spec.js`: Playwright Electron desktop plus persisted-files seam. Tests use disposable vaults and controlled clock/timezone/OS dispatch.
- `tests/repair.spec.js`: thirteen desktop/file repair cases cover independent annotations, moved paths, duplicate canonical choices, missing/conflict recovery and annotation-specific linkHolds. Twelve passed together; the thirteenth passed focused with an actual-main crash boundary. Full thirteen-case and final combined checks remain pending. Immutable `link-<UUID>.json`/held peer evidence and ledger linkHolds retain mixed source and independent writing for explicit retry and later #13 ownership-aware deletion.
- `app/codex.js`, `codex-rpc.js`, `codex-policy.js`, `codex-isolation.js`, `codex-turn.js`: ticket 8 setup state, private managed App Server lifecycle, dedicated-home policy, real named-profile Windows canary probes, and fresh-thread terminal handling. No auth files or exported tokens are read. `codex-view.js` owns the setup panel. Capture does not depend on Codex readiness.
- `tests/codex.spec.js`: desktop/file acceptance tests with an external stdio child fixture. Fixture results never establish live readiness. `scripts/codex-gate.cjs` drives the same adapter for root-owned live checks; `docs/verification-ticket8.md` records actual evidence and unpassed gates.
- `app/native/codex-read-probe.c` plus its compiled artifact/manifest: reviewed Kernel32-only Windows read-denial probe, reproducibly built by `scripts/build-codex-probe.ps1`. `app/codex-probe.js` verifies pins and copies the helper into the isolated working directory. PowerShell/Node crypto startup failures were not treated as file denials. The full actual direct/child/case/extended/junction matrix passed under the unchanged strict profile.

Remaining lifecycle work extends intake. Preserve capture timestamps, independent user writing and journaled publication. Imported stages never use quick-capture recovery. Intake metadata is vault authority and must not roll back during later app-history restoration. Recovery files can mix source snapshots with unpublished independent annotation text; later deletion must preserve that writing before purging source copies.

Settings are outside the vault in Electron user data. Captures, annotations, ideas, briefs and revisions occupy separate areas under the selected parent. Capture support began in #2; Project Brief support is described below. No retention expiry exists.

## Project Briefs (#7)

- `app/briefs.js`: vault-backed local extraction, append-only proposal/failure records, approved version files carrying their SHA256 in the filename, strict retained snapshot/reference validation, current source checks, and exact version lookup for downstream conversation pinning. Full selected source text is retained. Nothing is shortened automatically.
- `app/briefs-lock.js`: cross-process kernel ownership for every brief mutation, keyed by canonical selected parent path. Windows named pipes and Linux abstract sockets release on process death; no PID/stale-file reclamation. Version allocation and exclusive publication stay in the same lock. Busy attempts preserve the editor for explicit retry.
- `app/briefs-ipc.js`: OS file selection and serialized brief mutations; renderer cannot supply arbitrary source paths to reads. Source selection is explicit and not recursive.
- `app/briefs-view.js`: local source/passages inspection, editable text and validated source:line references, explicit approval, staleness/failure warnings and preserved approved history.
- `tests/briefs.spec.js`: approved desktop plus persisted-files seam, disposable selected documents and OS dialog substitute. `brief-pin` reads and validates only candidates for the requested approved numeric version, so unrelated damaged proposals/newer approvals cannot block a healthy historical pin. It returns the exact approved version, retained sources and current source warnings; unavailable, damaged or ambiguous requested versions fail rather than substitute another version.

Local extraction is a transparent heading-based draft, not a model summary or semantic verification. User edits remain identified as user writing. Conversation UI and complete outgoing context limits remain downstream responsibilities.

## Daily Windows intake (#6)

- `app/schedule.js`: installation-local anchor, desired lifecycle state, exact task identity, due-slot admission inside the existing Intake lock, coalescing, terminal diagnostics. A failed/interrupted admitted scheduled attempt consumes that due slot; explicit Check now retries, while the next daily slot remains eligible. First/manual checks do not consume scheduled slots.
- `app/task-scheduler.js` and `task-scheduler.ps1`: fixed no-shell adapter, JSON stdin, exact owned task lookup; InteractiveToken/least privilege, infinite PT24H, UTC first boundary A+24h, no intentional wake, missed-run availability and IgnoreNew. Pause gates queued launches, resume retains A, disable removes only the exact task, repair validates ownership/action before update. Effective trigger/count/boundary/repetition/expiry/catch-up/wake/overlap settings are inspected separately and drift stays visible until repair. Native boundaries ceil to whole seconds; application anchors stay exact.
- `app/main.js --intake-worker --schedule-file <absolute>`: headless early lifecycle path; never creates a BrowserWindow. Uses the same Intake.reconcile and lock as source connection, first scan and Check now.
- `tests/schedule.spec.js`: desktop plus resulting files/history, controlled time and OS task boundary; headless subprocess is real Electron. `scripts/probe-scheduled-intake.cjs` is a root-only disposable native integration tool, not application startup behavior.

## Finalized reviews (#4)

- `app/intake-review.js`: portable finalized bundle integrity, schema and human-label semantics, score recomputation, reviewed export selection, rejection metadata and normalized independent review/extraction/processing fields. It never opens producer paths retained in source provenance.
- `app/producer-json.js`: bounded source JSON parsing with lossless numeric tokens and Python storage.digest serialization. Exact original `source.json` text is retained in review snapshots. Runtime capability is checked through real Electron acceptance, not inferred from standalone Node.
- `tests/reviews.spec.js` and `tests/fixtures/reel-review/`: approved desktop/files workflow and producer-library-generated authored synthetic fixtures; source/video integration evidence remains separate. Finalized fixture bytes use `-text` because manifest hashes include producer CRLF bytes.
- `app/intake.js` connects by canonical folder plus kind, retains noncurrent drafts/reviews through `retainOnly` source transactions, and selects an existing reviewed snapshot through normal journaled publication with unique `resolution` backups. `capture.reviewChoices` pauses eligibility until explicit selection. `.intake/ledger.json` also owns reciprocal changed-byte associations; captures and histories remain separate.
- Source inspection shows processing, extraction, human findings, eligibility and exact retained revisions independently. `reviewSourceText` preserves source digest fidelity. It may contain private provenance/raw response and is not an automatic context source. Discovery must check capture eligibility/ambiguity and `revision.supportEligible`; rejection never becomes supporting evidence through a later draft or an association.
Codex's separate `codex/managed-home` belongs to App Server and may contain managed credentials. Companion never reads/copies auth files. Future history export/restore must whitelist history data and exclude this managed home; do not archive the whole application-data directory. Readiness reports contain safe evidence, never a reusable certificate.

## Vault repairs (#5)

- app/repairs.js extends Intake under its existing kernel lock: independent annotation Markdown, current verified identity/path reconciliation, exact duplicate-copy choices, missing restore/scoped intake removal, and user-controlled conflict transfer.
- Vault.scan reads ordinary accessible vault Markdown by stable identity. A complete scan precedes move/missing classification; inaccessible storage is a global access failure. Imported capture.relative is a validated vault-relative destination. Duplicate choices preserve every file and reopen when acknowledged copy bytes change.
- Annotation, relationship-link and repair intents journal exclusive staged publication. Current user title, original identity/instant and historical archive bytes survive conflict resolution. Each resolution uses its durable UUID for separate conflict/deferred archives. Source-specific failure clears a completed annotation intent only after safely retaining the incoming journal, allowing independent intake/restart.
- Reviewed-current conflict repairs retain the immutable incoming candidate while restoring the current reviewed snapshot through a keptCurrent resolution reference. Existing ledger attempts and exact snapshot hashes are revalidated before annotation/note mutation and final publication; reviewed ambiguity remains.
- tests/repair.spec.js is the approved desktop/files seam (nine observed passing cases). Actual Obsidian remains unavailable; URI-dispatch fixtures are a separate limited boundary check.
- Failed kept-current repairs retain schema-1 `.intake/repair-<resolution UUID>.json` intent copies (annotation/source text) plus their explicit conflict transaction. Kept-snapshot failures always establish explicit conflicts requiring fresh transfer, never automatic deferred publication. Active recovery clears only after durable source-specific hold; #13 deletion must enumerate these copies and unexpected aliases remain preserved.
- .intake/ledger.json is vault authority, outside app-history rollback. Future #13 deletion must enumerate accepted snapshots, source-bearing original/resolution conflict/deferred journals, all relevant stages/before-files/intents, current moved paths and acknowledged duplicate copies. Explicit missing-note intake removal retains that history and suppresses automatic return.

- Restored capture backup detachment requires the current ledger conflict transaction, unique verified identity/path, previous bytes/current ledger hash and exact inode/device peers. A deterministic `.detach.json` intent names one UUID `.detached-<UUID>` peer and `.independent` stage; backup publication is exclusive, and recovery handles moved/published/cleaned states while final capture guards remain single-link strict. Known ordinary editor recreations retain typed evidence and exact intent bytes in immutable `.detach.json.held-<UUID>` archives plus a source-specific block hold; independent intake continues after safe active-intent cleanup. #13 must preserve editor-writing evidence separately from source cleanup and enumerate all these source-bearing paths; exact schema is in verification-ticket5.md.
