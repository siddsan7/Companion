# Runtime map

- `app/main.js`: Electron lifecycle; folder-selection/settings, IPC, clock and Obsidian OS boundary. `COMPANION_TEST_ROOT` substitutes those boundaries for disposable acceptance runs.
- `app/preload.js`: narrow renderer-to-main bridge. Renderer Node access is disabled; sandbox, context isolation, CSP and blocked network/navigation apply.
- `app/vault.js`: authoritative Markdown capture store. Exclusive staged publication, stable UUID frontmatter, first capture instant, derived/editable title, user excerpt provenance. No index or database owns note content.
- `app/repairs.js`: shared-lock conflict transfer, missing/duplicate identity choices and guarded relationship journals. Vault-wide validated annotation scans retain moved-note associations; annotation duplicate choices use `annotation:<UUID>` keys separately from capture choices. Only the immediate generated header link after the first frontmatter block is repair-owned. Editor conflicts retain immutable link intent/peer evidence and an annotation-specific ledger hold; explicit retry rechecks current identities/bytes while source intake continues. Independent body text remains user-owned.
- `app/renderer.js`, `index.html`, `style.css`: capture, timezone-aware Today, history/search, title edit, open-note workflow.
- `app/intake-producer.js`, `producer-schema/`: Reel to MD draft envelope, strict schema/semantic revalidation, bound-excerpt restrictions, stable multi-file read and exact inert/redacted notes comparison. Supported draft review is unreviewed; extraction completeness and uncertainty are separate.
- `app/intake.js`: vault-owned `.intake/ledger.json`, immutable accepted attempts separate from locator outcomes, staged snapshot/journal publication, title intent recovery, immutable `Revisions/<uuid>.json`, source-byte grouping and distinct producer attempts. Source conflicts retain incoming/local/previous versions and pause that source while independent intake continues. Capture access failures defer per source; only explicit Check now retries them. Stage/final files require ordinary contained files and exact known hardlink peers for recovery. It does not copy media. Source connection, first/manual checks and scheduled/catch-up workers share this entry point and native lock.
- `app/intake-lock.js`: canonical-vault kernel-owned named-pipe lock on Windows; process death releases it without racing stale PID reclamation. Reconciliation, connection and imported title mutation use the same lock.
- `app/intake-view.js`: source connection, first-scan choice, held reasons, last check and source/revision inspection. Sections have named navigation as the shell grows.
- `tests/capture.spec.js`: Playwright Electron desktop plus persisted-files seam. Tests use disposable vaults and controlled clock/timezone/OS dispatch.
- `tests/repair.spec.js`: desktop/file repair cases cover independent annotations, moved paths, duplicate canonical choices, missing/conflict recovery, annotation-specific linkHolds and backup-detachment crash recovery. The integrated 98-case gate passed 97 tests with one Windows file-symlink capability skip. Immutable repair/link journals, detach intents and retained peers can contain the only unpublished independent writing; #13 deletion must preserve it. See `docs/verification-ticket5.md` for exact archive schemas and evidence.
- `app/codex.js`, `codex-rpc.js`, `codex-policy.js`, `codex-isolation.js`, `codex-turn.js`: ticket 8 setup state, private managed App Server lifecycle, dedicated-home policy, real named-profile Windows canary probes, and fresh-thread terminal handling. No auth files or exported tokens are read. `codex-view.js` owns the setup panel. Capture does not depend on Codex readiness.
- `tests/codex.spec.js`: desktop/file acceptance tests with an external stdio child fixture. Fixture results never establish live readiness. `scripts/codex-gate.cjs` drives the same adapter for root-owned live checks; `docs/verification-ticket8.md` records actual evidence and unpassed gates.
- `app/native/codex-read-probe.c` plus its compiled artifact/manifest: reviewed Kernel32-only Windows read-denial probe, reproducibly built by `scripts/build-codex-probe.ps1`. `app/codex-probe.js` verifies pins and copies the helper into the isolated working directory. PowerShell/Node crypto startup failures were not treated as file denials. The full actual direct/child/case/extended/junction matrix passed under the unchanged strict profile.

Remaining lifecycle work extends intake. Preserve capture timestamps, independent user writing and journaled publication. Imported stages never use quick-capture recovery. Intake metadata is vault authority and must not roll back during later app-history restoration. Recovery files can mix source snapshots with unpublished independent annotation text; later deletion must preserve that writing before purging source copies.

Settings are outside the vault in Electron user data. Captures, annotations, ideas, briefs and revisions occupy separate areas under the selected parent. Capture support began in #2; Project Brief support is described below. No retention expiry exists.
