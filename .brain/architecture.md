# Runtime map

- `app/main.js`: Electron lifecycle; folder-selection/settings, IPC, clock and Obsidian OS boundary. `COMPANION_TEST_ROOT` substitutes those boundaries for disposable acceptance runs.
- `app/preload.js`: narrow renderer-to-main bridge. Renderer Node access is disabled; sandbox, context isolation, CSP and blocked network/navigation apply.
- `app/vault.js`: authoritative Markdown capture store. Exclusive staged publication, stable UUID frontmatter, first capture instant, derived/editable title, user excerpt provenance. No index or database owns note content.
- `app/renderer.js`, `index.html`, `style.css`: capture, timezone-aware Today, history/search, title edit, open-note workflow.
- `app/intake-producer.js`, `producer-schema/`: Reel to MD draft envelope, strict schema/semantic revalidation, bound-excerpt restrictions, stable multi-file read and exact inert/redacted notes comparison. Supported draft review is unreviewed; extraction completeness and uncertainty are separate.
- `app/intake.js`: vault-owned `.intake/ledger.json`, immutable accepted attempts separate from locator outcomes, staged snapshot/journal publication, title intent recovery, immutable `Revisions/<uuid>.json`, source-byte grouping and distinct producer attempts. Source conflicts retain incoming/local/previous versions and pause that source while independent intake continues. Capture access failures defer per source; only explicit Check now retries them. Stage/final files require ordinary contained files and exact known hardlink peers for recovery. It does not copy media. Source connection/first check/manual checks share this entry point; scheduling will call it later.
- `app/intake-lock.js`: canonical-vault kernel-owned named-pipe lock on Windows; process death releases it without racing stale PID reclamation. Reconciliation, connection and imported title mutation use the same lock.
- `app/intake-view.js`: source connection, first-scan choice, held reasons, last check and source/revision inspection. Sections have named navigation as the shell grows.
- `tests/capture.spec.js`: Playwright Electron desktop plus persisted-files seam. Tests use disposable vaults and controlled clock/timezone/OS dispatch.
- `app/codex.js`, `codex-rpc.js`, `codex-policy.js`, `codex-isolation.js`, `codex-turn.js`: ticket 8 setup state, private managed App Server lifecycle, dedicated-home policy, real named-profile Windows canary probes, and fresh-thread terminal handling. No auth files or exported tokens are read. `codex-view.js` owns the setup panel. Capture does not depend on Codex readiness.
- `tests/codex.spec.js`: desktop/file acceptance tests with an external stdio child fixture. Fixture results never establish live readiness. `scripts/codex-gate.cjs` drives the same adapter for root-owned live checks; `docs/verification-ticket8.md` records actual evidence and unpassed gates.
- `app/native/codex-read-probe.c` plus its compiled artifact/manifest: reviewed Kernel32-only Windows read-denial probe, reproducibly built by `scripts/build-codex-probe.ps1`. `app/codex-probe.js` verifies pins and copies the helper into the isolated working directory. PowerShell/Node crypto startup failures were not treated as file denials. The full actual direct/child/case/extended/junction matrix passed under the unchanged strict profile.

Next seams: annotations and identity/conflict repair, and scheduled worker registration extend intake. Preserve capture timestamps, independent user writing and journaled publication. Imported stages never use quick-capture recovery. Intake metadata is vault authority and must not roll back during later app-history restoration.

Settings are outside the vault in Electron user data. Captures, annotations, ideas, briefs and revisions occupy separate areas under the selected parent. Capture support began in #2; Project Brief support is described below. No retention expiry exists.

## Project Briefs (#7)

- `app/briefs.js`: vault-backed local extraction, append-only proposal/failure records, approved version files carrying their SHA256 in the filename, strict retained snapshot/reference validation, current source checks, and exact version lookup for downstream conversation pinning. Full selected source text is retained. Nothing is shortened automatically.
- `app/briefs-lock.js`: cross-process kernel ownership for every brief mutation, keyed by canonical selected parent path. Windows named pipes and Linux abstract sockets release on process death; no PID/stale-file reclamation. Version allocation and exclusive publication stay in the same lock. Busy attempts preserve the editor for explicit retry.
- `app/briefs-ipc.js`: OS file selection and serialized brief mutations; renderer cannot supply arbitrary source paths to reads. Source selection is explicit and not recursive.
- `app/briefs-view.js`: local source/passages inspection, editable text and validated source:line references, explicit approval, staleness/failure warnings and preserved approved history.
- `tests/briefs.spec.js`: approved desktop plus persisted-files seam, disposable selected documents and OS dialog substitute. `brief-pin` reads and validates only candidates for the requested approved numeric version, so unrelated damaged proposals/newer approvals cannot block a healthy historical pin. It returns the exact approved version, retained sources and current source warnings; unavailable, damaged or ambiguous requested versions fail rather than substitute another version.

Local extraction is a transparent heading-based draft, not a model summary or semantic verification. User edits remain identified as user writing. Conversation UI and complete outgoing context limits remain downstream responsibilities.

## Finalized reviews (#4)

- `app/intake-review.js`: portable finalized bundle integrity, schema and human-label semantics, score recomputation, reviewed export selection, rejection metadata and normalized independent review/extraction/processing fields. It never opens producer paths retained in source provenance.
- `app/producer-json.js`: bounded source JSON parsing with lossless numeric tokens and Python storage.digest serialization. Exact original `source.json` text is retained in review snapshots. Runtime capability is checked through real Electron acceptance, not inferred from standalone Node.
- `tests/reviews.spec.js` and `tests/fixtures/reel-review/`: approved desktop/files workflow and producer-library-generated authored synthetic fixtures; source/video integration evidence remains separate. Finalized fixture bytes use `-text` because manifest hashes include producer CRLF bytes.
- `app/intake.js` connects by canonical folder plus kind, retains noncurrent drafts/reviews through `retainOnly` source transactions, and selects an existing reviewed snapshot through normal journaled publication with unique `resolution` backups. `capture.reviewChoices` pauses eligibility until explicit selection. `.intake/ledger.json` also owns reciprocal changed-byte associations; captures and histories remain separate.
- Source inspection shows processing, extraction, human findings, eligibility and exact retained revisions independently. `reviewSourceText` preserves source digest fidelity. It may contain private provenance/raw response and is not an automatic context source. Discovery must check capture eligibility/ambiguity and `revision.supportEligible`; rejection never becomes supporting evidence through a later draft or an association.
Codex's separate `codex/managed-home` belongs to App Server and may contain managed credentials. Companion never reads/copies auth files. Future history export/restore must whitelist history data and exclude this managed home; do not archive the whole application-data directory. Readiness reports contain safe evidence, never a reusable certificate.

## Local context (#9)

`app/context.js` owns eligibility, deterministic exact-word paragraph matching, source/project association reasons, exact excerpt approvals and package serialization. `context-view.js` owns inspection/manual selection. The narrow `context-*` IPC never dispatches, authenticates or reads history. See ../docs/verification-ticket9.md for evidence and final gates.

Intake identity wins over writable capture type. Imported support uses validated immutable snapshots plus current eligibility. Annotations carry their own content hash and an explicitly unversioned capture association; their creation revision is unknown. Explicit note scope is stored in application-data `context-settings-<vault-path hash>/notes.json`, published atomically under the existing kernel-owned helper keyed to that dedicated directory.

Provisional #11 reader: `artifact_type: saved_idea`, `schema_version: 1`, stable `companion_id`, explicit `source_dependencies`. Imported dependencies use actual `capture_id`/`revision_id`; quick captures use `capture_id`/`content_sha256`. Unknown attribution is unavailable; explicit `[]` means independent user writing. Optional `project_brief_version` must pin a valid approval. The exported injectable `validateDependencies` adapter leaves room for retained quotations/turn-package references. No idea authoring/migration is implemented here.

Full-source, line-range and contiguous-shortening choices remain exact. Ranges index displayed eligible text. Approvals bind vault/source/digest/text; source/brief removal excludes actual dependent context without changing notes. Canonical LF package text is counted as Unicode code points and hashed as UTF-8. Default cap:32000; smaller bounds need main-owned verified evidence. No live model bound exists. Renderer generations suppress stale preview successes/errors.

Final #5 sync must use guarded cross-vault annotations, namespaced `annotation:<id>` identity choices, and exact immediate generated-header stripping while preserving independent Source: lines. #10 must derive history dependencies from durable records, revalidate eligibility/bounds before dispatch and re-present changed snapshots. Root owns this synchronization and final combined/exact-tip review.
