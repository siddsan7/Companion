The pending promise exists only while local work is active. Each request keeps its selected Vault, and explicit capture and intake keep the request clock. A changed selection rejects a queued request before its body. Native storage still uses the same kernel lock. Another process can still receive a real busy error; no operation replays. Schedule reads/recording and IPC result delivery do not hold the local sequence.

`app/renderer.js` keeps Save and vault setup mutually unavailable until their own work settles, and preserves edits typed while a previous draft saves. Connect and Check share pending controls and publish only their current status. `app/ideas-view.js` reports a durable saved idea after its own support inspection settles; support warnings remain separate from note publication. Late delivery cannot replace a newer view or re-enable a stale confirmation.

`npm run check` verifies tracked UTF-8 and syntax plus the existing native probe pins. `npm run prepare:electron` verifies the pinned Windows runtime before desktop tests. Native scheduler and actual producer probes run only as explicit developer commands with disposable roots. See [ticket 16 verification](../docs/verification-ticket16.md) for actual, controlled and deferred boundaries.
