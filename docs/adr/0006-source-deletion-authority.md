# Keep deletion authority separate from source bytes and producer facts

Capture deletion records an exact, content-free manifest and a new source generation in the intake ledger before removing any source files. Recovery uses that committed scope; a changed file or unknown recovery copy holds the operation. Independent writing and quotations remain unless separately selected, and mixed recovery records must first preserve verified independent writing. Lock order is Conversation, any required independent writing stores, Intake, then selected Vault files.

Restoration deliberately admits selected validated producer material as a fresh revision and generation. Original accepted producer identities, fingerprints and literal checksums remain immutable. Additive generation-qualified admissions preserve those facts while allowing restoration after a snapshot purge. Generation metadata binds selections, approvals and dependencies separately from content digests, so identical restored text cannot revive old history authority. Rehydrating old snapshots or replacing literal checksums would blur intentional deletion with continuous evidence eligibility. Legacy absent generation is eligible only while the source has never acquired generation authority.
