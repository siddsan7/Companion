## Runtime ownership and context contract

`app/conversations.js` owns ordinary history, source/history assembly, qualified resolution and dispatch. `app/conversation-controls.js` shares that live store and kernel lock for local deletion, generation/scope authority and explicit deletion/restoration recovery. `app/transcripts.js` owns readable-copy publication; its new-publication lock order is conversation store, then managed transcript journal. Ideas and archives share the same Conversations instance; comparisons share the provider while retaining their separate store.

A package's source dependencies are `{key,digest,captureId?,revisionId?}`. Same-conversation `historyIds` are ordered earlier request UUIDs. Optional `historyRefs` are exact `{conversationId,requestId,digest}` records, including conservative foreign ancestry. Digest resolution binds original request, exact brief and current originating scope, plus generation when present. Origin generations changing may make old foreign refs conservatively unavailable; restoration never invents rewritten origins. Raw primary foreign dialogue, provenance and dependency descriptors enter the actual serialized text and Unicode code-point count before the application/provider limit is checked.

Optional package `conversationGeneration` binds a current own-conversation approval. A controlled record's optional `generation` must match local active authority. Fresh restoration also changes scope version, so old approved own or foreign packages cannot append to a new generation merely because original request bytes match. Both optional fields are strictly whitelisted UUID/null archive metadata. Legacy absent-generation/no-local-control archive additions retain their previous exact-record behavior; imported generations are inert and rebind locally.

Initial support inspection waits for an actual successful base refresh, including its awaited repair read; current configuration/vault epochs fence the completion event and support list. Busy failures do not fabricate readiness. Prior repair DOM is retained only within the same vault until a fresh result succeeds. This is a bounded correction for the observed startup contention, not universal interleaving coverage.

Support inspection uses one current Context corpus, which reads saved-note metadata directly and does not call Ideas.list. It checks capture/revision-or-digest attribution, duplicates/unknown attribution, exact brief shape/current reader eligibility and current canonical source eligibility. Identity availability remains the unique ordinary note's property. Ephemeral `reviewSupport`/`supportWarnings` change display only; no warning field is persisted to Markdown or made dispatch authority. Refresh/list/evidence/error responses are fenced by current request/view/vault ownership.

Deletion persists its content-free tombstone before unlinking only the reviewed exact manifest. Inspection/cancel cannot create that authority. Recovery accepts absent already-removed targets but refuses changed bytes/identity, unknown pending attribution, aliases and peers. Restored old leaf bytes alone cannot restore authority or enable resave. Saved writing, original project/producer material, transcript journals and external exports are not traversed as targets.

For successful fresh scope changes on active records, only explicitly restored exclusions are lowered from the prior floor before record save. Added exclusions are not installed ahead of a possibly failed file write. After the durable record save, its full scope is committed to control before issuing a send token. The tested before-store failure preserves old bytes/prior exclusions and allows reload/retry. The report does not generalize that one failure boundary into every possible multi-file storage interruption.
