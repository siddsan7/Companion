# Domain docs

Companion uses a single-context layout.

- Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/` before exploring domain code. If these records are absent, continue.
- Use glossary terms in issue titles, proposals, hypotheses, and test names. Note vocabulary gaps for `domain-modeling`.
- If a proposal conflicts with an ADR, cite the ADR and explain why the decision may need to be revisited.
- Add glossary entries and ADRs as terms and decisions are settled.
